# Tests et résultats

Commande : `tests/run.sh` (bac à sable : HOME jetable, dépôts jetables, faux serveur GitLab local). Option `COMPAT_REPO=<projet>` : contrôles supplémentaires sur une **copie** d'un projet réel (lecture seule).

Résultats de la distribution : voir `RAPPORT_DISTRIBUTION.md` fourni avec l'archive (sections, nombre de tests, exécutions).

| Section | Nature |
|---|---|
| 1. Structure du kit (skill unique, frontmatter, références, cascade guard, agents sans écriture, routage, statuts, garde-fous, triage en deux temps) | statique |
| 2. review-guard durci (autorisations, refus Bash, refus des outils d'écriture) | exécution du hook |
| 3. Règles natives et `rules_sync` | exécution des scripts |
| 4. Configuration de projet et détection du registre | exécution de `pm_config.py` |
| 5. Installateur et rollback | exécution en bac à sable |
| 6. Tests négatifs : conflit de noms, installation existante, permissions, état git, dépendance manquante, reprise interrompue | exécution en bac à sable |
| 7. Scope projet et adaptateur | exécution en bac à sable |
| 8. Compatibilité : projet GitLab multi-équipes synthétique (+ copie d'un projet réel si `COMPAT_REPO`) | exécution sur fixture |
| 9. Workflow GitLab simulé (create → doing → blocked → close) | glab contre faux serveur local |
| 10. Distribution : arborescence `~/.claude`, liste blanche `.gitignore`, clone simulé, configuration existante, mise à jour par `pull`, rollback `--all`, absence de données sensibles, `~/.claude` réel intact | exécution en bac à sable |
| 11. Pilote d'orchestration (`tests/pilot/test_pmx.py`, 29 tests) : registre unique, débat borné, plan (collisions, cycles, chemins sensibles), parallélisme, arrêt critique, relances (cause répétée, plafond), reprise, intégration locale contrôlée ; commandes de test non approuvées ou à substitution shell refusées ; checkout altéré (fichier, HEAD, références, nettoyage impossible) → `INCONCLUSIVE` avec preuve conservée ; intégration refusée sans confirmation au terminal (pseudo-terminal) | agents factices, dépôts jetables |
| 11 bis. Adaptateur docker (`tests/pilot/test_docker.py`, 26 tests ; ignoré sans Docker ou sans l'image locale `alpine:3.22`) : contrôle de la configuration réelle avant démarrage ; refus des clés de montage, de privilège ou de réseau ; deux conteneurs simultanés jusqu'à l'intégration ; sondes de séparation entre deux équipes (fichiers, HOME, secrets, socket Docker, réseau, privilèges, processus, montages, liens) ; arrêt critique, délai, reprise d'un conteneur orphelin ; mémoire (OOM), CPU (bridage), processus (fork bomb) ; lien symbolique et FIFO détectés ; **vérification isolée** : lecture du HOME et d'un secret, réseau, écriture hors checkout, HEAD et `.git`, fichier non suivi, échec de nettoyage, conteneur interrompu, image absente (sans repli sur l'hôte), configuration de l'exécuteur, politique d'isolation obligatoire ; cycle complet avec hooks versionnés, filtre et `textconv` globaux jamais exécutés par pmx ; contraste avec le mode hôte non isolé | conteneurs réels, agent factice |
| 11 ter. Passerelle réseau (`tests/pilot/test_gateway.py`, 9 tests ; partie Docker ignorée sans `alpine:3.22` ou sans l'image Python épinglée) : politique de destination sans Docker (privé, loopback, métadonnées, `docker.internal`, ports Docker, rebinding) ; avec des services amont **simulés** sur un réseau interne : routes autorisées vers les faux Anthropic et OpenAI ; refus des routes d'une autre équipe, inconnues, intranet, métadonnées, API Docker, loopback, redirections, URI absolues et CONNECT ; jetons inconnus, absents, expirés, volés et rejoués depuis un autre réseau ; taille (413), délai (504), réponse tronquée ; quotas par équipe ; aucun accès direct ; passerelle injoignable depuis l'hôte et le réseau par défaut ; ni clé ni jeton dans les journaux ; configuration incapable d'affaiblir l'isolation ; cycle complet de deux équipes parallèles jusqu'à l'intégration | conteneurs réels, agents et API simulés |
| 11 quater. Profil hybride `host-agents+docker-verification` (`tests/pilot/test_hybrid.py`, 15 tests, dont le confinement natif : profil exigé, prérequis absents, sandbox Codex ouvert ou cassé ⇒ arrêt avant tout agent, bloc `sandbox` utilisateur refusé, arguments générés ; vérification ignorée sans Docker) : exigences du profil (vérification en conteneur, politique d'isolation, agents sur l'hôte, réglages Claude refusant `docker`) contrôlées dès la première commande ; tout contournement des permissions natives refusé dans tous les modes ; Docker introuvable ⇒ `INCONCLUSIVE`, jamais de repli sur l'hôte ; cycle complet avec deux équipes sur l'hôte ; arrêt sur dépassement de périmètre ; pointeur `.git` redirigé détecté avant toute commande Git ; exemple `adapters/pilot-hybrid/` conforme | agents factices sur l'hôte, conteneurs réels |

Validation **réelle** du pilote, hors suite (opt-in, consomme de l'usage, CLI connectées par l'humain) : `PMX_LIVE=1 python3 -I -B tests/pilot/live_claude_cli.py <dossier-neuf>`.

**Ces tests sont statiques ou simulés : ils ne valident pas le chargement réel dans une session Claude Code** (voir `INSTALL.md` § Vérification) ni un GitLab réel.
